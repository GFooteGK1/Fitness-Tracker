## Documentation Guidelines

### When to Create New Session Docs

- Major feature completion
- Significant architectural changes
- Important bug fixes or investigations
- Handoff between development sessions

### What to Include

- Context: What was the goal?
- Changes: What was modified?
- Decisions: Why were choices made?
- Status: What's complete vs pending?
- Next steps: What should happen next?

### Naming Convention

- Current state: `CURRENT-STATE-YYYY-MM-DD.md`
- Feature docs: `FEATURE-NAME-DESCRIPTION.md`
- Session summaries: `SESSION-SUMMARY-YYYY-MM-DD.md`
