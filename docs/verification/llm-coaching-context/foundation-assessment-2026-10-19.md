## Verdict

Evolve incrementally. Socius has useful durable-data, authorization, provenance and deterministic-domain seams already. A rewrite would discard substantial behavior without resolving the current evidence gaps. The working external read connection is a credible foundation for an owner pilot; a dependable daily coach and generally least-privilege external platform are not yet established.

## Reusable and evidenced

- One external factual reader composes existing owner data, independent of a mandatory model call. The tool accepts only offset/window, never owner identity or a mutation operation (`app/lib/coach/coaching-context-tool.ts:8-18,52-85`). A fixture test verifies no network/model invocation during composition (`test/coach/coaching-context.test.ts:193`).
- Read effects are restricted by an allowlisted SELECT-only proxy, explicit owner filters and post-read owner rejection (`app/lib/coach/coaching-context-server.ts:16-59`). Bearer verification checks signature, issuer, resource audience, dedicated client, exact scope, expiry, provider owner and active grant (`app/lib/auth/coaching-oauth.ts:60-100`). This path uses an owner-scoped client, not a service-role fallback.
- Saved programming is read through the active accepted-plan pointer, with plan/program/session linkage checks; proposals explicitly cannot replace it (`app/lib/coach/coaching-context-server.ts:92-143`). Requirements include latest-version, withdrawal, effective/review dates and provenance (`app/lib/coach/coaching-context.ts:77-96`). These are good durable context boundaries.
- History already distinguishes event date, capture/revision lineage, source path, actual versus unconfirmed prescription, imported/model-estimated provenance, unknown quantities and logging coverage. Bounded output reports omissions instead of silently clipping records (`app/lib/coach/planning-context.ts:37-83`; `app/lib/coach/performed-work-context.ts:23-99`).
- Deterministic calculations are separable and versioned, e.g. the Epley estimate explicitly retains source and formula (`app/lib/coach/policy.ts:66-91`). Goal/measurement/assessment contracts are generic rather than APEX-only (`app/lib/coach/planning-intent.ts:9-39`; `app/lib/coach/adaptive-programming-contracts.ts:14-28`). Existing provider selection is also behind a seam (`app/lib/llm/client.ts:54-74`), although a server-model provider switch is different from a user-selected external harness.
- The sanitized release checkpoint records an actual owner-grant-preserving code exchange, canonical deployment checks and parent-observed real `get_coaching_context` partial retrieval. It separately records unverified refresh and failed browser answer rendering. These distinctions should remain.

## Must address before relying on coaching

1. **Current athlete declarations and plan.** The actual packet lacks structured training intent and a saved current-date session. The accepted plan remains historical. This is missing/stale durable state, not demonstrated plan-reader failure. Retrieval must not invent updated constraints, accepted plans, numeric goals or verified adherence. Acceptance should bind a fresh session/rationale to the actual current requirements, saved-plan authority and explicit gaps (`coaching-context-server.ts:180-225`).
2. **Recent-work evidence and completeness.** The live packet's disabled history means the harness cannot yet compare today's session with recently logged work. The current task's narrow reader-only addition is appropriate. Keep source provenance, local window, truncation/missing/error distinctions and foreign-owner rejection; do not reinterpret no records as no exercise. Existing performed-work tests cover unconfirmed prescriptions, unreviewed imports, corrections, deletions, bounded output and foreign owners (`test/coach/performed-work-context.test.ts:101-222`). These tests alone do not establish hosted workout coverage.
3. **WHOOP event-time attribution.** Recovery/sleep/cycle ingest derives date from provider `created_at` and discards the original event/interval timing (`app/lib/whoop/sync-service.ts:244-257,296-310,349-361`). The reader truthfully exposes UTC date-only precision and `observedAt:null`, and declines current-local-day use near UTC/local rollover (`app/lib/coach/coaching-context.ts:99-120`). A stale label is not proof sync failed. Preserve source intervals/timestamps/timezone and define recovery-day attribution before making day-specific recovery adjustments; do not weaken the warning.
4. **Qualify the context and validation contract, not more embedded programming.** Code/tests establish software behavior, not training efficacy or revalidated targets. `initialDosePolicy` is hard-disabled (`app/lib/personalized-coaching-capabilities.ts:7-8`); the reviewed production issuer registry is empty and separately gated (`app/lib/coach/reviewed-proposal-service.ts:6-12`). Existing adaptation constants (`app/lib/coach/adaptation-evaluator.ts:30-33`) are historical app policy, not automatically scientific authority or future restrictions on the selected LLM. Expose current requirements, evidence, uncertainty and deterministic calculations faithfully; let the selected LLM propose the program. Any future saved-plan operation must separately validate identity, structure, invariants and acceptance without reinstating a mandatory app-generated prescription engine.

## Material limits and brittleness

- **Tool read-only is not credential least privilege.** The owner credential retains broader rights, explicitly demonstrated in disposable PostgreSQL tests (`test/database/coaching-context-owner-boundary.test.ts:5-6,26-44`). RLS fixture tests support owner separation, not a complete audit of every hosted table/RPC. The original requested OAuth resource remains unattested; the pilot uses a dedicated client/scope/audience mapping. These accepted pilot limitations require a distinct design before general distribution or delegated roles.
- **Consistency is bounded, not atomic.** Assembly compares two reads of sources, saved programming and proposals and retries changed sources (`coaching-context-server.ts:165-178`), explicitly labelled `application_double_read_not_transaction_snapshot` (`217`). That cannot establish a database-wide snapshot or detect every ABA transition. New source types must be covered by the consistency contract or explicitly disclosed; history/evidence source mutations deserve targeted tests.
- **Temporal conventions and schema generations need care.** Raw and negated offsets coexist (AGENTS timezone section; `performed-work-context.ts:105-114`). History supports a legacy schema fallback; saved plans and activity blocks have multiple formats. These adapters are useful compatibility seams, but transitions need contract tests. Offset-only requests also cannot fully encode an IANA timezone's DST history for long windows.
- **Presence is not activation.** The architecture map documents many retained-local or uninstalled programming migrations and incomplete real Auth/browser flows (`docs/architecture/ARCHITECTURE-MAP.md:16-176`). Do not infer hosted readiness from source volume, the AGENTS “Production Ready” label or local test counts. The map's read-connection status is now stale relative to the newer release receipt.
- **Operability has a base, not complete proof.** Recorded release manifests, drift guards, staged/canonical probes and rollback references are valuable. Refresh/rotation/account-switch behavior and a usable fresh-browser coaching answer remain unverified. Avoid recreating connections as a shortcut. WHOOP transformation error paths log full provider records/user identifiers (`sync-service.ts:259-265,312-318,363-369`); prioritize minimizing/redacting those logs before expanding sensitive production integrations.
