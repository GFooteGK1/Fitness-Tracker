## Positive checks and boundaries

- New feedback-v2 fields start unknown, explicit no pain is distinct, optional energy can be cleared, and unknown pain does not display a new warning. Readiness, hardest-set/effort and session RPE remain separate concepts.
- New-request provenance is derived from validated supplied values; SQL independently validates it. Stored typed completion-RPE evidence is gated by a real same-owner/source-session check-in, source revision, exact reported RPE and matching event time. Legacy completion-generated RPE is excluded from new explicit-report gates despite its old stored verification flag.
- `weekly-review.ts` and the legacy in-memory weekly summary preserve concerning pain while excluding unproved legacy effort/energy from explicit gates. Denominators show reported effort per completed session.
- The signal module implements capture and a factual actual-work summary only. It imports no experimental numerical progression, requested-load, confidence, fit, RIR conversion or new physiological policy.
- SQL remains the authoritative completion guard when saved actual amounts/deviation/stop conflict with as-prescribed completion. It serializes the source session and rolls back canonical writes if the check-in is rejected.
- Accepted plans remain unchanged, and authoritative review/acceptance transitions remain separate. Feature flags are server-derived and default off.
