## Behavior and authority

The new `app/lib/recommendations` modules select one dated action, defined signal request, or abstention without an LLM. Existing accepted plan/review/proposal transitions retain authority. Confirmed current concerning pain uses the existing review boundary. Missing baseline requests keep exact goal/protocol/binding. Logged nutrition requires confirmed intent plus an explicit saved target; estimates, unknown/partial coverage and coverage-through time remain visible. No wearable trend, causal benefit, new calorie target or new numerical dose is selected.

GET and one bounded POST refresh use authenticated owner identity; source queries use RLS. Only trusted service-role RPCs claim, publish, fail or derive outcomes. Shown acknowledgement is explicit. Done/Not applicable/Adjust/Defer use payload-matched response RPCs and separate response revision. Missing source data yields unavailable, not invented cold-start advice. Application-source failure cannot change a successful canonical save.

Meaningful fingerprints include authority and rule facts, with canonical source ordering. Audit revisions and target update timestamp noise do not resurrect dismissed duplicates. SQL preserves the old decision snapshot when a current equivalent decision is reused. Lease tokens, current source/response revisions, plan/intent, runtime, local date/timezone and deadline fence publication/read/response. Exact candidate suppression lookup preserves long-lived dismissals. Outcomes distinguish self-report, comparable canonical observation and unknown; later source changes append invalidation and never imply causation.

Coach receives the same persisted current recommendation ID/reasons outside the passive cache. Permanent legacy filters and unknown-target/current-wearable source checks are separately reviewed. Rollback does not re-enable retired assertions.
