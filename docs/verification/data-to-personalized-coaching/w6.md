# W6 targeted review and execution priority

Local implementation; no provider calls, production changes or newly approved numerical policy. Parent owns Beads and handoff. Independent application and database reviews pass; see `w6-app-review.md` and `w6-database-review.md`. Parent closed W6 after independent clearance.

## Outcome and policy boundary

`targeted-review.ts` evaluates every active confirmed outcome from the accepted intent snapshot. It retains the exact goal ID, metric, assessment and protocol versions, movement, variation, distance, equipment and test context. Equivalent distance/load/time units normalize without filling missing context. Each outcome records included/excluded observations, its evaluator result, independently computed target attainment, candidate action, exact assignment IDs and deferred/selected/held disposition. Attainment stays true when concerning pain overrides the action; it does not imply the other outcomes or whole event are attained.

Numerical eligibility requires the **existing direct evidence requirement's exact metric, assessment and catalog protocol**, not merely a supported measurement family. A velocity goal therefore cannot inherit a repetition-max policy's set progression. Unsupported adapters hold/collect; no load-trial or other unreviewed numerical rule from `422fd3a` is enabled. A supporting proxy/training signal is used only when the accepted hypothesis already declares that requirement and its exact outcome context matches. The existing evaluator still owns exposure counts, meaningful-change thresholds and specificity decisions.

`weekly-review.ts` applies safety before explicit goal priority. Competing changes with unspecified priority, conflicting shared assignments or unresolved evidence for shared allocation remain held. Missing evidence for an unrelated outcome is recorded independently and does not veto an otherwise valid unchanged week. One numeric change requires one exact observed movement/requirement assignment. Multiple matching assignments or broad domain-only evidence cannot pick the first sorted exercise. A missing exact assessment adapter records a collect-signal state rather than injecting a generic squat test. Accepted prescription content remains immutable.

The route no longer applies the first legacy domain goal filter when targeted review is enabled. It persists the complete per-goal audit plus unioned observation links, immutable execution revision bindings and exact measurement value IDs. `targeted-review-1` is additive; legacy records without it remain readable, future or malformed metadata is rejected safely. The current weekly selector algorithm is `weekly-review-0.3.0` and evidence selection is `coach-context-selection-0.3.0`.

## Current source validity and successor reviews

Current evidence selection checks owned canonical `capture_revision` and runner `execution_revision`; amended or missing executions cannot continue authorizing original quantity-based observations. Original check-ins and observations remain historical records. A failed current-revision read is an unavailable authoritative packet, not empty history.

Migration `20260918040000_targeted_review_sources.sql` and its docs mirror add an append-only, FORCE-RLS source invalidation table. Owner-bound activity revision and observation references record corrections, deletion and measurement retraction. Current review/proposal checks validate and lock exact owned measurement values, complete/verified groups, confirmed imports and current workout revisions. Workout locks precede observation locks to agree with W2 deletion. A correction between source read and review write rolls back the review. A correction/retraction after review creation blocks proposal creation/acceptance atomically. An already accepted proposal still replays its immutable accepted result.

Invalidated reviews gain an immutable successor, with `supersedes_review_id`, increasing `review_revision` and unique payload-matched request identity. Selection follows the chain leaf under the program lock, not transaction timestamps. Creating a successor expires only unaccepted old proposals and rejects their proposed plan versions, freeing the next-week window. Original review IDs/content and exact retry responses remain intact. The weekly UI offers a new review after invalidation, and an acceptance conflict refreshes this state. Invalidation reads remain active when the feature flag is off, check existence for each bounded displayed or pending review separately, and cannot hide one review behind a truncated list of another review's source changes. Legacy numeric reviews without current source contracts receive an explicit review-only `legacy_source_unverified` audit, allowing a successor without inventing source IDs. W2's audited canonical deletion detaches the workout FK while retaining original identity, measurement content and deletion revision provenance.

## Execution priority

The bounded audited ordering port uses an explicit leading strength goal and exact movement from the confirmed intent. It reorders existing assignments through mandatory sequencing, then derives preparation, title and role from the actual first work. It never changes allocated dose. Realization records achieved/blocked/unavailable from final exercises; unavailable equipment or movement preference cannot be claimed achieved. Stored-plan decoding recomputes realization and rejects mismatched metadata. Continuations retain the accepted profile/intent/history/priority snapshots. Program disclosures use readable assessment names, independent outcome attainment and concise priority status.
