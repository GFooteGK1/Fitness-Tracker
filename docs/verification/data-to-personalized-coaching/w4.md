# W4 factual history and shadow evidence

Local implementation in `data-to-personalized-coaching`; no provider calls, production writes, or numerical policy approval. Independent review remains separate.

## Runtime boundary

`planning-context.ts` reads bounded same-owner canonical workouts and immutable completion links. A missing new capture column permits a narrowly identified legacy read; connection failure, missing unrelated columns, or truncation are explicit unavailable/partial states. A failed read cannot generate a cold-start profile. Local-date boundaries use `timezone-utils` with the raw offset; rolling initial, conversion, and changed-direction requests send that offset. Old callers default explicitly to UTC.

New/changed directions call `refreshConfirmedPlanningContext`: current exercise preferences, confirmed intent when enabled, then independently gated factual history. The accepted continuation path keeps its saved profile. History adds no dose totals. Only athlete-reported movement identities or a matching immutable as-prescribed completion enable the existing movement familiarity score; legacy unknown origins remain visible as unknown and cannot claim performed familiarity. Current avoidance/equipment/restrictions remain authoritative. Outside training is explicitly unknown unless a caller supplies an owned reported reference; no current outside-training collection adapter is invented.

`prescription-basis.ts` records source IDs, capture cutoff, eligible movement familiarity, current constraints/equipment, missingness, and `provisional_existing_policy`. Optional Program details disclose this basis. Existing accepted profiles without this additive field render unchanged. No claim of tolerance, proficiency or history-derived numerical personalization is made.

## Source and replay semantics

`planning-history.ts` selects immutable `activity_revisions` by owner, original canonical identity and revision at the requested capture cutoff. Historical replay requires an actual immutable snapshot; reconstructed legacy rows cannot be backdated. Revision queries include terminal corrections/deletions even when their event moved outside the requested window, then filter the selected snapshot's event date. Canonical current deletion does not resurrect an older record. Conflicting identities/revisions, invalid snapshot identity and unavailable snapshots remain explicit exclusions.

W2 `capture_revision` is independent of runner `execution_revision`. Any canonical capture amendment above revision 1 invalidates the original as-prescribed completion as authority for current copied ranges. Original check-ins/observations remain immutable. **W6 must also exclude superseded quantity-based observation applicability using this capture revision/supersession information; immutable observation storage alone does not make old quantities current.**

## Shadow boundary

Audited pure `performed-dose-evidence.ts` and `performed-dose-review.ts` retain exact/bounded/unknown quantities, source paths, source capture time/revision, provenance, work/preparation roles, kg/lb/unknown units, unilateral conventions, protocol/equipment, and effort scope/scale. RPE is never converted to RIR. Hardest-set effort remains scoped. Legacy amounts are `legacy_unknown`; athlete confirmation does not turn a model estimate into an athlete report. Canonical prescription ranges stay bounded and require their own completion linkage; modified/stopped/amended records cannot borrow them.

The shadow modules have no runtime compiler or prompt import. `numericPolicyEligible` is literally false. A frozen-input compiler test checks identical output after shadow evidence changes; this proves deterministic compiler invariance, not live-model invariance. A separate runtime test demonstrates a reported movement can change only an existing eligible choice while scheduled numerical coverage remains identical, even with large raw fixture quantities.
