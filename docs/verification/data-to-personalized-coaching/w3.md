## Delivered behavior

`PlanningIntentV1` captures 1–8 separately identified outcomes including repeated domains, optional numeric targets, independent measurement bindings, explicit full priority order and optional event membership/date. Process/exploratory and unsupported outcomes remain representable. Unsupported outcomes remain visible; confirmed outcomes are not collapsed into legacy domain allocations. `assessmentContext` is an additive optional binding extension carrying repetitions, fixed load/duration and technique/environment details required by actual catalog protocols.

Authenticated intent confirmation/correction creates immutable goal-memory versions with server confirmation time and provenance; an additive strict database trigger protects generic memory paths too. Readers keep legacy `primary_goal` and accepted JSON intact. Versioned intent snapshots appear in the profile, direction, stored weekly intent and adaptive `confirmedOutcomes`; old shared schema versions did not change. New or explicitly changed directions refresh confirmed memory; ordinary continuations retain accepted snapshots. W4 now owns factual-history additions to the shared refresh wrapper.

Program setup starts with no training days/equipment and requires explicit availability confirmation. Valid saved setup/preferences are reused; missing or invalid setup needs correction. Profile/onboarding categories provide draft wording only, without inferred targets or automatic confirmation. No additional body-metric form was introduced. The UI edits protocol context, event membership and priority, shows unsupported outcomes, and preserves separate athlete acceptance of any proposed week.

The baseline endpoint derives metric/protocol/source from an owned confirmed intent and writes existing immutable observation tables. Manual numeric results are finite, range checked in canonical units and preserve fractional values. Exact frozen request identity persists across response loss/reload. The UI offers existing comparable observations before manual capture; the athlete must separately confirm baseline linkage. Supported source adapters are this manual baseline source and explicit `coach_completion`/`sociusfit` observations carrying completion-contract-v2 metadata, complete verification and canonical IDs. Group owner, verifying actor, complete state, definition/version, protocol/version, all comparison dimensions and the selected direct-outcome metric/unit must match. SQL repeats these checks at correction time.

Intent and baseline mutation payloads include `expectedUserId`; the authenticated session remains authoritative. The editor fences account changes and late responses. Pending envelopes persist in owner-scoped session storage; definitive 4xx responses release the edit lock. This is same-browser-session retry recovery, not the W2 offline IndexedDB queue.

## Review boundaries and remaining limitations

The initial numerical dose-policy gate remains false. W3 does not double-count same-domain demands or activate a plan. W6 must consume `confirmedOutcomes` for separate attainment and priority decisions; the legacy domain-level adaptive goal list is retained for compatibility.

Baseline matching is conservative and exact for frozen units/context; equivalent-unit goal identity is normalized by `outcomeBindingKey`, but changing the persisted test-context representation requires reconfirming a comparable baseline. Manual and scheduled-session observations preserve their own source identities; imported/device/derived observations are not silently admitted by this adapter. Candidate lookup is bounded to 32 recent complete owned observation groups and reports lookup failure separately. No event-specific scoring or unsupported capability is invented.

SQL/TypeScript schema parity covers required keys and malformed primitive cases. Parent review should scrutinize payload-size edge parity, source boundaries, simultaneous corrections, and changes to the shared refresh helper before Beads closure. The SQL draft intentionally embeds the reviewed catalog; a future catalog change needs a versioned migration and adapter review.

During development, the initial SQL validator caught an operator-precedence defect in JSON key subtraction; the caught exception was temporarily surfaced for diagnosis, all JSON accesses were parenthesized, and the full positive/negative suite now passes. Required-key/type sweeps then caught nullable SQL branches and text-coercion acceptance; explicit required keys/types and null-safe checks fixed those. A synthetic scheduled fixture initially violated required prescription/blocks and observation immutability constraints; it now inserts a valid immutable observation without disabling guards. These failures are resolved, not external blockers. `DEBUG_INTENT=1` is a local diagnostic that rethrows validator exceptions in the harness only.

## Independent-review repairs

The W4 owner independently found three W3 gaps, now repaired. New directions reject legacy domain allocations that conflict with or omit confirmed supported active outcomes; supported domains share a single allocation and preserve every distinct outcome binding. A confirmed priority must agree with the athlete-selected lead domain. The existing compiler supports at most three distinct domains, so broader requests stop with a visible capability explanation. Active unsupported event members prevent presenting a supported subset as a complete event program. Generic scheduled domain assessments are explicitly not advertised as attainment evidence for exact confirmed outcome tests; W6 owns exact per-outcome review/assessment matching.

Saved availability now validates the persisted fields themselves before form fallback. Invalid/missing saved duration, schedule or equipment cannot become confirmed through a default. Scheduled baseline candidates and new references now require a current same-owner workout with capture revision 1 and execution revision 0; amendments or deletion invalidate new linkage without rewriting old accepted snapshots.

The SQL harness now also executes actual W2 `20260918020000_capture_receipts.sql` and its nutrition/personal-record dependencies before the W3 draft.
